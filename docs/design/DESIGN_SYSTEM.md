# DESIGN_SYSTEM.md
### KSC Public Record Intelligence — visual and semantic system

Case: KSC-BC-2020-06 · Design complete · 21 artboards
All data in the prototype is mock. In production every figure is a live read from the records database.

**Universal chrome.** Every screen carries GlobalNav (52px, with the EN/SQ toggle in the right cluster), and every screen displaying a figure carries the DemoDataFlag. Both were audited across all 21 artboards; three Phase 1 screens were missing the language toggle and have been corrected.

---

## 1. The rule that governs everything

The interface never implies guilt. This is not a content guideline applied at the end — it constrains the colour system, the type system, the component set and the copy rules.

Three consequences that engineering must preserve:

1. **Colour encodes information type, never culpability.** Indigo means "this came from the court", not "this is bad". Red is used only for the `Contradicts` direction label and the Incident node shape, both of which are neutral record classifications. No colour is ever bound to a person.
2. **No score, rank, rating or weight of any person exists in the data model.** There is no field for it, so there is nothing for a future feature to accidentally render. Counts that do exist are reference counts, and every surface showing one carries the sentence explaining that.
3. **Provenance is a first-class visual property.** Record material and generated analysis are never rendered in the same container, the same colour, or the same border style. This is enforced structurally (see §6), not by convention.

### 2.3 Source provenance palette

This is the semantic core. Each value identifies **where a piece of information came from**.

| Source | Dark | Light | Badge bg (dark) | Meaning |
|---|---|---|---|---|
| Court Finding / Judgment | `#818CF8` | `#4F46E5` | `#1A1F35` | Determined by the Panel |
| Witness Testimony | `#38BDF8` | `#0284C7` | `#0F2030` | Said under oath in court |
| SPO Argument | `#34D399` | `#059669` | `#0A2018` | Asserted by the Prosecutor |
| Defence Argument | `#A78BFA` | `#7C3AED` | `#1A1030` | Asserted by the Defence |
| Document / Exhibit | `#FBB035` | `#B45309` | `#201A08` | A document in evidence |
| AI Analysis | `#F472B6` | `#DB2777` | `#25102A` | Generated by software |
| Incident | `#F87171` | `#DC2626` | `#281515` | An event alleged in the record |
| Location / Organisation | `#8B9BC0` / `#A78BFA` | — | `#1A2234` | Place, unit or body |

Two accent colours carry a second job:

- `#34D399` is both *SPO Argument* and *Human Verified*. Context disambiguates: as a source badge it reads "SPO Argument", as a verification badge it reads "Human Verified" with a tick glyph.
- `#F87171` is both *Incident* and *Unresolved citation*. Again glyph-disambiguated.

Engineering note: keep these as two separate token names (`--spo` / `--verified`) even though the hex matches today, so either can move independently.

### 2.4 Direction labels (evidence relative to a claim)

| Label | Colour | Glyph | Definition |
|---|---|---|---|
| Supports | `#34D399` | `↑` | Tends toward the claim in the same row |
| Contradicts | `#F87171` | `↓` | Tends against that claim as stated |
| Qualifies | `#FBB035` | `~` | Narrows or conditions without contradicting |
| Neutral | `#8B9BC0` | `—` | Addresses the subject without bearing |

Direction is **always measured against a specific stated claim**, never against a person. Every surface that shows direction labels carries the note saying so (Incident Detail 11, Finding Detail 05).

## 3. Typography

Two families only.

**DM Sans** — all interface text. Variable weight 300–700.
**Libre Baskerville** — legal text: judgment paragraphs, transcript Q&A, exhibit quotations, prior statements. It appears nowhere else. Serif in this product is a signal, meaning "these are the words from the record".

| Role | Size / weight | Tracking | Notes |
|---|---|---|---|
| Page title | 28 / 700 | −0.02em | Homepage hero runs 40 / 700 at −0.03em |
| Screen title | 19–22 / 700 | −0.02em | Dossier and workspace headers |
| Section title | 14–16 / 600 | −0.01em | |
| Card title | 12.5–14 / 600 | — | Wraps to two lines at every breakpoint |
| Body | 12–13 / 400 | — | line-height 1.55–1.75 |
| Table cell | 11 / 400 | — | line-height 1 in compact density |
| Metadata | 10.5–11 / 400 | — | `--text-secondary` |
| Section label | 10 / 600 uppercase | 0.10em | `--text-muted` |
| Badge | 9–9.5 / 600 uppercase | 0.05–0.06em | |
| Governance footnote | 10 / 400 | — | `--text-faint`, line-height 1.5 |
| Legal quotation | 11–12.5 / 400 | — | Libre Baskerville, line-height 1.65–1.85 |

All numerals in tables, counts, citations, dates and identifiers use `font-variant-numeric: tabular-nums`. Identifiers (`W01234`, `P00441`, `¶1,204`, `T. 4,226`) are always tabular and always 600 weight in their source colour.

## 4. Spacing and layout

Scale: **4 · 8 · 12 · 16 · 24 · 32 · 48**. Internal component padding runs finer (5, 7, 9, 11, 13) because this is a dense research tool; the coarse scale governs layout gaps and section rhythm.

### Standard desktop chrome
```
Global nav          52px   fixed
Case stripe /       30–32px
  breadcrumb
Tab bar             38–40px
Content             flex
Governance footer   24–26px (where present)
```

### Standard three-region body
```
Left rail    214–246px   navigation, filters, chronology, categories
Centre       flex, min-width 0
Right rail   262–376px   inspector, analysis, sources, positions
```

Both rails collapse before the centre column at narrow widths. The centre column always carries `min-width: 0` so long identifiers cannot force horizontal scroll.

### Radii
`3px` badges · `5px` chips · `6–7px` buttons and inset rows · `8–9px` cards · `13px` command palette · `16px` bottom sheet · `26px` phone frame.

## 5. Elevation

Flat by default. Shadow is reserved for genuinely floating surfaces:

- Command palette: `0 24px 72px rgba(0,0,0,.66)` plus a `1px` accent ring
- Mobile bottom sheet: `0 -8px 28px rgba(0,0,0,.5)`
- Document page in the reader: `0 2px 12px rgba(0,0,0,.1)` on the light ground
- Focus: `0 0 0 3px` of the accent at 12–16% alpha, never a browser outline

## 6. The provenance boundary

The single most load-bearing piece of the system. On any screen that mixes record material with generated analysis (05, 09, 13, 14, 15, and the reader's context panel), the two are separated by **four simultaneous signals**:

1. **Container** — separate bordered blocks, never interleaved paragraphs
2. **Border style** — record blocks use a solid 1px border; AI blocks use a 1.5px **dashed** border
3. **Colour** — AI blocks use `#F472B6` on `#150C1C` / `#1A1024`, a hue used for nothing else
4. **A labelled divider** — a dashed rule reading *"Below this line: generated analysis, not the record"*

Plus a header band inside every AI block carrying the `AI Analysis` badge and the phrase *"Written by software · no part of this is a court record"*.

Removing any one of these four is a regression. Colour-blind users still get container, border-style and text; users who do not read the labels still get the visual break.

## 7. Copy rules

These are part of the design system, not editorial preference.

**Never written in the system's own voice:** *lying, dishonest, false, unreliable, guilty, culpable, suspicious, important* (as a ranking), *likely, probable, strong, weak* (as an assessment of a ground or a person).

Those words may appear **only** inside a quotation from an official court finding, in quotation marks, with a citation attached and the `Court Finding` badge present. Artboard 09 demonstrates the pattern.

**Required phrasings:**

- Appeal-adjacent surfaces use **"Potential Issues for Review"**, never "appeal risk", "appeal strength", "grounds ranked" or anything predictive.
- Reference counts are introduced as *"how many times this appears in the record. Not a measure of significance, involvement or responsibility."*
- Network edges carry *"A connection does not by itself imply wrongdoing, agreement, responsibility or guilt."*
- Direction labels carry *"measured against the claim in the same row, not against any person."*
- Gaps are stated: *"2 transcript pages are redacted in the public version"* — never silently omitted, never filled.

**Protected witnesses:** only the W-code, only the label *Protected Witness*, only a dashed neutral avatar. No name, image, location, occupation, age or inferred attribute is stored or displayed. Search does not resolve a name to a code. The Protection Notice component states this on every protected witness surface.

## 9. Iconography

All icons are inline SVG on a 12/14/16/20/24 grid, `stroke-width` 1.2–1.8 scaled to size, `stroke-linecap: round`. No icon font, no external sprite.

Network node shapes are semantic and fixed:

| Shape | Node type |
|---|---|
| Hexagon | Accused |
| Solid circle | Public witness |
| **Dashed circle** | **Protected witness** |
| Rounded rect (pill) | Court finding |
| Rectangle | Document / exhibit |
| Triangle | Incident |
| Diamond | Location |
| Rounded rect with clasp | Organisation |

Shape carries the type independently of colour, so the graph is legible without colour vision.

---

## 10. Accessibility floor

- Body text on `--surface` meets 4.5:1; labels at 10px meet 4.5:1 against their own ground
- Source colours are always paired with a text label — colour is never the sole carrier of meaning
- Node type is carried by shape as well as colour
- Provenance is carried by four signals (§6), only one of which is colour
- Focus is a 3px accent ring, never `outline: none` without replacement
- All interactive rows are ≥32px tall in compact density, ≥44px on mobile
