# Phase 21A Design Parity Audit

Date: 2026-09-25
Status: implementation audit complete; Phase 21 remains in progress
Design source: `docs/design/Design.html`

## Method

The actual bundled artboards were rendered in a browser and inspected, not
inferred from the current application or from memory. The comparison set was:

- `Home` (artboard 02);
- `06_Search`;
- `06b_SearchOverlay`;
- `10_Exhibits`;
- `DocumentReader` (source-action destination check);
- `17_Mobile`;
- `System`.

The real application was captured at 1440×1000, 1024×900 and 412×915 (Pixel 7
CSS viewport) for Home, Search, Documents and Evidence. The capture matrix is
generated by `tests/e2e/phase21a.spec.ts` and attached to the Playwright test
result. Each capture was compared side by side with its relevant artboard.

The comparison uses the held corpus. Prototype figures, identifiers, names,
quotes, relationships and statuses were not copied into the application.

## Global system and navigation

- Preserved the approved dark research surface and existing source-provenance
  tokens.
- Restored Overview as a real `/` primary destination and aligned the primary
  navigation order more closely with the artboard. Unsupported Judgment
  navigation was not added; the real Findings route remains the relevant
  destination.
- AI Research stays visually distinct and last in the primary sequence.
- The case stripe now carries the real case identifier, court name and a public
  record state. It does not claim a fabricated indexing time.
- Existing real routes for Incidents, Appeal and External Sources remain
  accessible through the responsive overflow rather than being removed.
- Search and directory layouts use continuous borders, dense rows and selected
  states instead of stacking generic cards around every region.

## Accessibility and integrity

- Changed routes pass automated axe checks on desktop and Pixel 7.
- All three target viewport groups have zero document-level horizontal
  overflow.
- `SEARCH MATCH` remains visibly and semantically separate from the persisted
  `VERIFIED MENTION` classification.
- Protected-witness payload/rendering, exhibit status semantics, citation
  resolution, SourceAnchor precision and version-safe Reader behavior were not
  changed.

## Known differences carried forward

1. Full route-by-route parity is 21B/21C work. This checkpoint does not restyle
   People, Witnesses, Findings, Network, Timeline, Appeal, AI, External Sources
   or the full Reader.
2. Search has no backend query-interpretation or related-entity payload. The UI
   exposes only the recognized identifier syntax and real returned records.
3. Command search intentionally omits unsupported contextual actions.
4. Documents and Evidence need richer list projections before every inspector
   field in the prototype can be populated. Missing values remain absent or
   explicitly unknown.
5. The held corpus has a narrow verified-findings set and many exhibits whose
   court status is unknown. The resulting visual sparsity is a truthful data
   property, not filled with prototype content.

These differences are non-blocking for 21A and are explicit inputs to the
later, separately authorized Phase 21 checkpoints.
