# Development

## Prerequisites

- Docker with Compose v2+
- Node 22 and pnpm 11 (`corepack enable`)
- Python 3.12

## First run (everything in Docker)

```bash
cp .env.example .env
docker compose up --build
```

Then:

- Web: http://localhost:3000
- API docs: http://localhost:8000/docs · `GET /health` · `GET /ready` · `GET /version`
- MinIO console: http://localhost:9001 (credentials from `.env`)

The API container applies migrations and seeds `KSC-BC-2020-06` on start.

## Host-side development

```bash
make setup      # venv + pip install -e apps/api[dev] + pnpm install
make infra      # postgres, redis, minio (+ bucket) in Docker
make migrate    # alembic upgrade head against localhost
make seed       # idempotent case metadata
make dev        # api (uvicorn --reload :8000) + web (next dev :3000)
```

## Quality

```bash
make lint        # ruff, ruff format --check, eslint, prettier --check
make typecheck   # mypy (strict), tsc
make test        # pytest (unit + integration) + vitest
make test-unit   # backend unit only, no infrastructure
make e2e         # playwright — needs a running stack and `pnpm exec playwright install`
make format      # ruff format, ruff --fix, prettier
make ci          # lint + typecheck + test
```

Integration tests create and migrate a throwaway `ksc_test` database on the
configured PostgreSQL. `make reset-db` destroys the Docker volumes.

## Layout conventions

- Frontend tests are colocated: `apps/web/src/**/*.test.tsx` (Vitest + Testing
  Library). Render through `src/test/render.tsx` to get i18n and theme providers.
- Backend tests live in `tests/unit` and `tests/integration` (pytest markers).
- Interface strings go in `apps/web/src/i18n/messages/{en,sq}.json` — never inline.
- Colours, radii, fonts and spacing come from tokens in `apps/web/src/styles/globals.css`.
- Routes come from `apps/web/src/lib/routes.ts`; a test checks every route has a page.
- `docs/design/` is read-only and excluded from Prettier.

## Migrations

```bash
make migration m="add witnesses table"   # autogenerate from models
make migrate
```

Review autogenerated migrations by hand; enum types need explicit `create_type`
handling (see `0001`).

## Adding a screen (Phase 5+)

1. Read the screen's entry in `docs/design/PAGE_SPECS.md` and the components it
   lists in `COMPONENTS.md`.
2. Replace the `PlaceholderScreen` in the route's `page.tsx`.
3. Every figure comes from the API (later) or is marked with `DemoDataFlag`.
4. Add the screen's required governance text to the string tables.
5. Tests for any rule the screen encodes.

## Session procedure

Read `CLAUDE.md`, then `MEMORY.md`, then `docs/PROJECT_STATE.md`, then recent
entries in `docs/DECISIONS.md`; check `git status` / `git log`; continue from
`MEMORY.md → Next Actions`. Update `MEMORY.md` at the end of every session.
